# ExtensionMesh governance

## Purpose

ExtensionMesh is an open project for practical extension distribution through
independent registries. Governance exists to keep technical direction,
participation and project identity transparent as the project grows.

This is a lightweight model for the current early stage. It can evolve through
the public decision process described below.

## Project model

ExtensionMesh is maintainer-led and developed in public.

Maintainers are responsible for repository quality, releases, security and
scope. They should seek consensus for meaningful decisions. When consensus
cannot be reached, the responsible maintainers make and document the decision.

## Roles

### Contributors

Anyone who reports issues, proposes designs, improves documentation, submits
code or provides implementation feedback is a contributor.

### Maintainers

Maintainers have write or review responsibility for one or more repositories.
They review contributions, manage releases and protect the scope and health of
their repositories.

Maintainer access is based on sustained, constructive contribution and the
needs of the project. Existing maintainers grant and review that access.

### Organization maintainers

Organization maintainers manage shared infrastructure, repository ownership,
project-wide policies and the ExtensionMesh identity. They should avoid
overriding repository maintainers on implementation details without a
project-wide reason.

## Decisions

Routine implementation decisions happen through issues and pull requests.

Changes that affect multiple repositories, public interfaces, governance,
licensing or project positioning should:

1. begin with a public issue;
2. state the problem, constraints and alternatives;
3. allow reasonable time for relevant contributors to respond;
4. record the outcome and its reasoning.

Security-sensitive details may be discussed privately until disclosure is safe.

## Repository autonomy

Connectors and other components may have their own maintainers, release cadence
and technical constraints. Organization-wide policies apply unless a repository
documents a justified exception.

Shared interfaces should be extracted from demonstrated common requirements,
not assumed in advance.

## Commercial participation

Individuals and organizations may use ExtensionMesh to distribute extensions,
operate registries or provide related services. Commercial use does not grant
special control, priority or endorsement.

Contributors should disclose a material commercial interest when it is relevant
to a project decision. Technical decisions should be justified by project needs
and documented trade-offs.

## Conduct and removal

Maintainers must follow the same Code of Conduct as all contributors. Access may
be limited or removed for security risks, sustained inactivity, misuse of
project privileges or serious conduct violations.

## Changing this document

Governance changes require a public issue and pull request in this repository.
