# Contributing to ExtensionMesh

Thank you for helping build ExtensionMesh. Contributions can include code,
documentation, testing, issue reports, design work and implementation feedback.

## Choose the right repository

Open the issue or pull request in the repository that owns the affected
component. This repository contains organization-wide community files only.

If the correct location is unclear, open a focused issue in the most relevant
repository and explain which part of the project it concerns.

## Before starting

For substantial changes, open an issue before implementation. Describe:

- the problem or use case;
- the affected component;
- the proposed direction;
- compatibility or migration concerns.

Small corrections and clearly scoped fixes may go directly to a pull request.

## Contribution guidelines

- Keep changes focused and reviewable.
- Add or update tests when behavior changes.
- Update documentation alongside public behavior or interfaces.
- Use English for public project communication and documentation.
- Avoid introducing general abstractions without a demonstrated need.
- Keep system-specific behavior in its connector unless it is already shared
  by multiple proven implementations.
- Do not include secrets, private customer data or proprietary source material.

## Pull requests

A good pull request explains why the change is needed, what changed and how it
was validated. Draft pull requests are welcome for early technical feedback.

Maintainers may request changes to preserve project scope, compatibility,
security or maintainability.

## Licensing

By contributing, you agree that your contribution may be distributed under the
licenses declared by the target repository. Make sure you have the right to
submit all included material.
